# Plan 08-01: End-to-End Verification

**Phase:** 8 - End-to-End Verification
**Goal:** Full flow verified, zero CRIT/HIGH findings, memory stable
**Depends on:** Phase 7 (all prior phases complete)

## Requirements Covered

- VERIFY-01: Full flow: Title -> CharSelect -> Embark -> Overworld
- VERIFY-02: VB Code Reviewer: zero CRITICAL/HIGH in modified files
- VERIFY-03: Unity Profiler: Texture2D count stable across transitions
- VERIFY-04: Frame time: no GC in hot paths, stable 60fps at 1080p

## Approach

This phase has 4 verification steps that map to the GSD workflow's built-in checks:

1. **Static Analysis** (VERIFY-02): Run VB_CodeReviewer headless scan on all C# runtime files. Count CRITICAL and HIGH findings. Target: zero.

2. **Scene Flow Verification** (VERIFY-01): Verify that all scene files exist and load correctly. Check:
   - Title scene loads without errors
   - CharacterSelect scene exists and has required components
   - Overworld/Battle scenes exist
   - VBSceneManager transition paths are valid

3. **Memory Leak Audit** (VERIFY-03): Static code analysis for Texture2D leaks:
   - new Texture2D() without Destroy() (BUG-38 rule)
   - Resources.Load without caching (BUG-21 rule)
   - UITextureRegistry tracks runtime textures (Phase 5 deliverable)

4. **Performance Hot Path Audit** (VERIFY-04): Static code analysis for GC allocations in hot paths:
   - new List/Dictionary/HashSet in Update (BUG-04)
   - String concatenation in Update (BUG-05)
   - LINQ in Update (BUG-28)
   - GetComponent in Update (BUG-01)
   - Material property writes in Update (PERF-22)
