## REMAINING BUGS (CRITICAL)

### 1. MANA BAR STILL GREEN
**Root cause:** `CharSelectVisualEnhancer.ApplyStatBarGradients()` bakes a GREEN gradient texture onto `stat-stamina-fill` at init time. When `HeroDataPanelController.UpdateResourceStatLabel()` swaps the CSS class to `stat-chip-mana`, the USS color changes but the C# background-image gradient OVERRIDES it (background-image has higher priority than background-color in UI Toolkit).
**Fix:** Subscribe to `CharSelectEvents.OnHeroChanged` in CharSelectVisualEnhancer and re-apply the correct gradient (green for stamina, purple for mana) to `stat-stamina-fill` based on the hero's path. The purple gradient colors are: `rgb(130,80,200)` → `rgb(180,130,255)`.
**Files:** `Assets/Scripts/UI/CharacterSelect/CharSelectVisualEnhancer.cs`

### 2. TWO TRANSPARENT BOXES ON TITLE SCREEN
**Status:** Unknown source. All MainMenuController overlays removed. TitleScreenVFX vignette/atmosphere disabled. rootBackground forced transparent in both code AND scene file.
**Debug approach:** Use Unity's UI Toolkit Debugger (Window > UI Toolkit > Debugger) in play mode. Pick the element visually to find which VisualElement has a background-color or background-image that creates the box. Likely candidates:
- `logo-container` (480px tall, should be transparent)
- `video-overlay` element created by TitleScreenVFX
- Some VFX layer in TitleScreenVFX (_vfxContainer, _frontVfxContainer)
- The `main-container` element from MainMenuBootstrap
**Files:** `Assets/Scripts/UI/Core/TitleScreenVFX.cs`, `Assets/Scripts/UI/Menus/MainMenuBootstrap.cs`

### 3. EMBARK BUTTON DOESN'T WORK (HOLD-TO-CONFIRM)
**Status:** The ClickEvent was removed from CharacterSelectManager (was single-click embark). HoldToEmbarkController uses PointerDown/PointerUp events and should work. The button text says "HOLD TO EMBARK" but holding does nothing.
**Debug approach:** Add `Debug.Log` in HoldToEmbarkController.OnPointerDown to verify events fire. Check if `HandleScreenReady` is called (the method that registers the pointer events). The AutoWire method needs UIDocument and CharSelectFocusManager passed in — verify these are set.
**Files:** `Assets/Scripts/UI/CharacterSelect/HoldToEmbarkController.cs`, `Assets/Scripts/UI/CharacterSelect/CharacterSelectManager.cs` (line 269-274)

### 4. HERO THEME COLORS DON'T MATCH BACKGROUNDS
**Issue:** Nyx is cyan/blue theme but has red/warm scene background. Orion is red theme but scene is blue. The info panel border uses `var(--hero-primary)` which is correct per spec, but the 3D scene backgrounds don't match.
**Fix:** This is a SCENE issue, not USS. The `CharSelectEnvironmentController` or camera background needs to change color when heroes change. OR accept the theme colors as-is (the spec doesn't define 3D backgrounds).
**Files:** `Assets/Scripts/UI/CharacterSelect/CharSelectEnvironmentController.cs`

### 5. CARD COLORS WRONG FOR SOME HEROES
**Issue:** Per-hero card gradient detection uses `card.ClassListContains("hero-card-{heroId}")`. If CarouselController doesn't add these classes, detection fails and cards get base gradient only.
**Fix:** Check `CarouselController.cs` to see what classes it adds to cards. May need to match on a different class or data attribute.
**Files:** `Assets/Scripts/UI/CharacterSelect/CarouselController.cs`, `Assets/Scripts/UI/CharacterSelect/CharSelectVisualEnhancer.cs` (DetectHeroIdFromCard method)
